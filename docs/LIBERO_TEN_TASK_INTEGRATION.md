# LIBERO-Object ten-task integration

## Scope

This is an integration experiment for **one shared Muse/SAM-conditioned action
policy**, warm-started from the successful milk checkpoint. It is not evidence
that the policy can reliably solve ten tasks. The ten LIBERO-Object tasks use
different grocery targets and the same basket-placement outcome, Panda arm,
and OSC_POSE controller. They do not cover ten different action primitives.

The task registry is generated by `odvla/vla/libero_object_tasks.py`; the
actual prepared source IDs and episode splits are recorded in
[`configs/libero_object_10_prepared_registry.json`](../configs/libero_object_10_prepared_registry.json).
All ten official HDF5 source files were downloaded and checked against their
published SHA-256 hashes. A separate metadata audit matched the declared robot,
controller configuration, control rate and camera conventions across all ten.
This is not a substitute for recorded-action replay on every task.

For each of the nine new tasks, five demo IDs are reserved for development and
five for evaluation; 40 are assigned to training. Milk keeps its existing
34/8/8 split. The milk evaluation IDs were used previously and are **not** an
untouched test set. An exact `states[0]` hash audit found no overlap between
the demo-ID partitions within each task; different state hashes do not by
themselves establish meaningful scene diversity. No evaluation actions or
closed-loop evaluation were executed in this integration.

## Real inputs and what was trained

- One selected training demonstration per task was regenerated from simulator
  `states[t]`: 1,474 total 512×512 RGB frames, aligned 15-channel robot
  observations, and seven-channel `action[t]` labels.
- Frozen SAM 3.1 generated target/basket measurements for those episodes.
  Initialization uses assistant-proposed, task-specific points inspected on
  first-frame RGB, not autonomous instruction-to-object selection. Chocolate
  pudding is heavily occluded in its first frame; its target mask has not been
  independently verified. The preview is
  `/libero/ten_task_integration_v1/sam_initialization_preview.png` on the Modal
  volume. Incremental tracking matched exact observed-prefix replay at frames
  0 and 9 of each episode; that is not an all-frame tracking-quality audit.
- Training retains all **34 original milk training episodes** alongside the
  selected episode from each of the nine other tasks. A sampler chooses task,
  then training episode, then window; task identity is used for sampling and
  reporting, not to select a task-specific controller.
- The frozen NF4 Muse layer-26 encoder receives the image and the task's actual
  instruction. The existing query-normalized prefix and action expert remain
  trainable; SAM and Muse stay frozen, and the dynamics objective remains off.
  The original milk `stats.npz` is reused rather than silently changing the
  normalization coordinates of the warm-start weights.
- Muse features are computed on demand and placed in a **2 GiB** byte-bounded
  least-recently-used cache. An evicted feature is recomputed; the trainable
  prefix is not cached or frozen. The cache key includes task, episode, frame,
  instruction, image checksum, model and processor revisions, date, and
  backend precision identity. This is a single-worker cache, not a distributed
  cache service. The 2 GiB limit applies only to this new feature cache, not
  the entire volume: original model weights, source data, and the older full
  milk cache still occupy storage separately.

## Executed integration result

A real H200 integration first completed two optimizer updates, then resumed to
**20 updates** with effective batch 64, starting from milk checkpoint
`fed8976c64c4b0842cb9158b675501c18d4ac8c8b2ae248e0aa1ff7947600bc2`
with a disclosed optimizer restart. The resumed run restored the new optimizer,
sampler and random-state checkpoint. All ten tasks appeared among its 1,280
sampled windows; per-task counts were 111, 134, 128, 138, 128, 124, 116,
135, 141 and 125 in registry order. The final cache held 2,142,695,917 bytes,
below its 2 GiB (2,147,483,648 byte) limit; the resumed chunk recorded 264
hits and 918 misses. The frozen milk-image Muse hash matched the original
baseline.

Changing the instruction on the same image changed the Muse feature hash. With
the same robot/SAM observations and sampling noise, the two sampled first
actions differed by at most **0.00104** in any raw action channel. That single
probe shows feature sensitivity but does not demonstrate correct language-based
target selection; the very small action change is a limitation worth investigating.

The job saved `/eval/muse_ten_task_integration_v1/last.pt` and `report.json` on
the `object-dynamics-vla-data` volume. A separate frozen copy is at
`/eval/muse_ten_task_frozen_v1/checkpoint_20.pt`. The 20-update checkpoint SHA-256 is
`7c86adc0fa8f941b8deb21048aa36efa54bdc190ca7dba7e1843922a55c4d39e`;
the same run may be resumed, in which case `last.pt` will advance. Offline
per-task first-action errors were recorded for three **training** windows per
task, not held-out initializations or control success. The earlier two-update
checkpoint SHA-256 was
`6a6292d5da6ce0fab11b7ce797ea42eeb2fe019858fb4c2eeda03562920aa15d`.

Run the existing bounded integration on the prepared workspace with:

```bash
python -m modal run --detach -m scripts.modal_muse_ten_task_integration --updates 40 --max-seconds 1200 --cache-gib 2 --resume --background
```

This uses GPU credit. It needs the prepared source, rendered/SAM data, frozen
Muse and reference model assets, original milk split and checkpoint on the
authorized Modal volume. It does not automatically run simulator rollouts.

## Bounded closed-loop integration smokes

`scripts/modal_muse_ten_task_rollout.py` loads the same frozen 20-update
checkpoint for each task. Before any action, it compares the training and live
initial RGB, Muse feature, robot state, SAM measurement, and visibility mask;
tracking is also checked against prefix replay at selected steps. The task's
instruction is given to Muse and the manually selected target/basket points to
SAM; the action expert is shared rather than switched by task.

All ten tasks completed a **30-action** smoke on their selected training
initialization after passing initial parity checks against the frozen 20-update shared
checkpoint. No task reached simulator success within those 30 actions. This
verifies the end-to-end action loop, not task success or failure: the cutoff is
shorter than the 166 actions needed by the earlier milk success. It does not
measure held-out generalization. Each row below corresponds to one selected
training demo; no per-task reliability rate is implied.

`scripts/run_ten_task_smokes.py` limits parallel jobs and checks the delayed
Modal billing summary before launching more. Its `--max-credit-used` setting
is a conservative operational guard, **not** a hard invoice cap. The local
supervisor needs the computer to stay awake. Individual reports are stored on
the Modal volume under `/eval/ten_task_<object>_smoke_v1/`; the BBQ A100 retry
uses `/eval/ten_task_bbq_sauce_a100_smoke_v1/`. The local
`outputs/ten_task_smoke_results.json` includes the failed original BBQ attempt
as well as the successful 30-action integration retry.

The initial BBQ-sauce smoke stopped before acting because H200 SAM's basket
measurement differed from the A100-prepared training measurement by at most
0.000097. A subsequent one-action diagnostic using frozen SAM on A100 restored
exact initial parity. The 30-action BBQ retry used that A100 tracker while
Muse remained on H200; it executed all 30 actions without reaching the success
condition. The exact parity gate was not relaxed, and this completed retry is
reported separately from the original failed attempt.

## Milk retention check

The frozen 20-update ten-task checkpoint was also run on milk's `demo_0` for
up to 200 actions with seed base 7. It passed initial RGB, Muse, robot, SAM,
and visibility parity checks, but **did not reach simulator success in 200
actions**. The earlier frozen milk checkpoint succeeded in 166 actions on the
same initial state. The saved noise hashes match for all 166 corresponding
actions; the initial robot and SAM measurements also match exactly. The
sampled first actions differ by a maximum of about 0.299 in a raw action
channel. This is evidence of a changed outcome for one matched seed and
initialization, not a statistical estimate of forgetting or a causal isolation
of dataset coverage from the additional training updates.

The retention report and video are stored at
`/eval/ten_task_milk_retention_seed7_v1/` on the Modal volume. The successful
original milk checkpoint remains unchanged and is the separately documented
`fed8976c…` baseline.

## Remaining work

The present fixture covers only one new-task demonstration each; expand the
rendering, alignment and task-specific SAM initialization beyond that fixture
before describing it as full ten-task training. Validate prompt identities,
especially the occluded target, and develop instruction-grounded autonomous
target selection. Run reserved-initialization, per-task closed-loop rollouts,
same-scene instruction comparisons and retention tests with the actual new
checkpoint. Two updates or a decreasing training loss cannot establish those
outcomes. CPU suite after integration and aggregation checks: **70 tests passed**.
